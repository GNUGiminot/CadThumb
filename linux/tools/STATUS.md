# Verification status (rootless WSL sandbox)

Built without sudo by downloading `.deb` packages with `apt-get download`/`--print-uris` and extracting
them with `dpkg-deb -x` into `~/sysroot` (see `env.sh`, `configure_and_build.sh`, `extract_sysroot.sh`).

**All CadThumb C++ source files compiled successfully** against OpenCASCADE 7.6.3 (Ubuntu 24.04's
`libocct-*-dev` packages) after two real, now-fixed compatibility issues:
* `STEPCAFControl_Reader::SetMetaMode` does not exist before OCCT 7.7 — guarded with
  `#if OCC_VERSION_HEX >= 0x070700` in both `linux/src/render/StepLoader.cpp` and the Windows
  `src/render/StepLoader.cpp` (harmless there too, since vcpkg's OCCT is 8.0).
* miniz needs a `miniz_export.h` normally generated by its own CMake build; added a static
  replacement at `linux/third_party/miniz/miniz_export.h`.

**Blocked at the final link step**, sandbox-only: Ubuntu's OCCT packages record an unconditional
`IMPORTED_LOCATION`-style dependency on `/usr/lib/x86_64-linux-gnu/libfreeimage.so` on at least one
`TK*` target in the XCAF/CAF dependency chain (present even with only `TKXDESTEP TKSTEP TKXCAF
TKRWMesh TKMesh TKBRep TKTopAlgo TKGeomAlgo TKGeomBase TKG3d TKG2d TKMath TKernel TKXSBase TKLCAF
TKCAF TKCDF TKShHealing` linked, i.e. without `TKVCAF`/`TKV3d`/`TKService` explicitly). CMake writes
this as a literal Makefile file-prerequisite (not just a linker flag), and unlike GCC's own
`--sysroot` handling, CMake's Makefile generator does not remap it into the rootless sysroot — it
checks the real, unwritable (no sudo in this session) `/usr/lib/x86_64-linux-gnu/libfreeimage.so`
directly, which does not exist there.

**On a normal system with `sudo apt install` used as intended, this is not an issue**: installing
`libocct-data-exchange-dev` (etc.) for real puts `libfreeimage.so` at that exact real path via its
own dependency on `libfreeimage-dev`, so the prerequisite is satisfied naturally.
